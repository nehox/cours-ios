Étape 0 console.firebase.google.com

Créer le projet Firebase et enregistrer votre app iOS

Firebase est un ensemble de services proposés par Google. Ici, nous utilisons uniquement Firebase Authentication, qui gère les comptes et les connexions à votre place.

1. Ouvrez console.firebase.google.com et connectez-vous avec votre compte Google.
2. Cliquez sur Créer un projet, donnez-lui un nom (par exemple le nom de votre app), puis validez. Google Analytics n'est pas nécessaire pour ce TP.
3. Dans la page du projet, cliquez sur l'icône iOS+ pour ajouter une application Apple.
4. Saisissez votre Bundle Identifier exactement comme dans Xcode. Il ressemble à com.votrenom.monapp. Un caractère différent et Firebase refusera la connexion.
💡 Où trouver le Bundle Identifier ? Dans Xcode : cliquez sur le nom de votre projet > target de l'app > onglet Signing & Capabilities > champ Bundle Identifier. Copiez-le sans le modifier.
Le Bundle Identifier est l'identité unique de votre application. Firebase l'utilise pour savoir à quelle app iOS appartiennent les requêtes d'authentification. Si vous créez plusieurs apps dans le même projet Firebase, chacune doit avoir son propre Bundle Identifier.
✓ Objectif de validation : La console Firebase affiche votre application iOS dans Vue d'ensemble du projet.
Étape 1 GoogleService-Info.plist

Télécharger et ajouter le fichier de configuration

Firebase vous fournit un fichier GoogleService-Info.plist qui contient les identifiants publics de votre projet. Sans ce fichier, l'application ne sait pas à quel projet Firebase se connecter.

1. Dans la console Firebase, cliquez sur Télécharger GoogleService-Info.plist.
2. Glissez le fichier dans le navigateur de projet Xcode, à la racine de votre dossier de code.
3. Cochez Copy items if needed et vérifiez que votre target d'application est cochée dans Add to targets.
❌ Erreur classique : le fichier s'appelle GoogleService-Info (2).plist ou il n'est pas coché pour votre target. Firebase échouera alors au démarrage. Le nom doit être exactement GoogleService-Info.plist.
Pour vérifier que le fichier est bien associé à votre application : sélectionnez-le dans Xcode, ouvrez l'inspecteur de fichiers à droite, et regardez la section Target Membership. La case de votre app doit être cochée.
✓ Objectif de validation : GoogleService-Info.plist apparaît dans Xcode et appartient à votre target.
Étape 2 File > Add Package Dependencies

Installer le SDK Firebase avec Swift Package Manager

Nous utilisons Swift Package Manager (SPM), intégré à Xcode. Aucun outil externe à installer, contrairement à CocoaPods.

1. Dans Xcode : File > Add Package Dependencies...
2. Collez l'URL : https://github.com/firebase/firebase-ios-sdk.git
3. Choisissez la version proposée par défaut (la plus récente), puis cliquez sur Add Package.
4. Cochez au minimum FirebaseAuth et FirebaseCore. Pour Google, vous ajouterez un second package à l'étape 8.
📦 Packages à ajouter maintenant : FirebaseCore FirebaseAuth
La résolution du package peut prendre plusieurs minutes. Attendez que Xcode ait terminé avant de compiler. Si Xcode affiche une erreur de résolution, vérifiez votre connexion Internet puis File > Packages > Reset Package Caches.
✓ Objectif de validation : Cmd + B compile toujours après l'ajout des packages.
Étape 3 VotreApp.swift

Initialiser Firebase au démarrage de l'application

Firebase doit être configuré une seule fois, au lancement de l'app, avant toute utilisation de l'authentification. Dans une app SwiftUI, on le fait dans le init() de la structure @main.

Remplacez MonApp et ContentView par les noms de votre propre projet. Ne créez pas un second @main : modifiez celui qui existe déjà.
VotreApp.swift 
import SwiftUI
import FirebaseCore

@main
struct MonApp: App {
    init() {
        FirebaseApp.configure()
    }

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
✓ Objectif de validation : L'app se lance sans crash et FirebaseApp.configure() est appelé au démarrage.
Étape 4 Authentication > Sign-in method

Activer les trois fournisseurs dans la console

Par défaut, aucun fournisseur n'est actif. Il faut autoriser explicitement Email/Mot de passe, Google et Apple dans la console Firebase.

Email / Mot de passe
Authentication > Sign-in method > Email/Password > Activer > Enregistrer.
Google
Même écran > Google > Activer > Enregistrer. Téléchargez ensuite un nouveau GoogleService-Info.plist et remplacez l'ancien.
Apple
Même écran > Apple > Activer. La configuration complète est détaillée à l'étape 10.
⚠️ Pour Google, Firebase demande parfois de retélécharger le fichier GoogleService-Info.plist après l'activation. Remplacez l'ancien fichier dans Xcode par le nouveau.
Si un fournisseur n'est pas activé, Firebase renvoie une erreur du type OPERATION_NOT_ALLOWED. Ce n'est pas un bug de votre code : retournez dans la console et activez le fournisseur.
✓ Objectif de validation : Les trois fournisseurs apparaissent avec le statut Activé.
Étape 5 AuthManager.swift

Créer le gestionnaire d'authentification

On centralise toute la logique Firebase dans une classe AuthManager conforme à ObservableObject. Les vues SwiftUI pourront ainsi observer l'état de connexion et se mettre à jour automatiquement.

user L'utilisateur Firebase connecté (ou nil).
isAuthenticated Vrai si la connexion a réussi.
errorMessage Le dernier message d'erreur à afficher.
1. @MainActor garantit que les modifications des propriétés se font sur le thread principal, celui de l'interface.
2. Task { } lance une tâche asynchrone : les fonctions Firebase peuvent prendre du temps (réseau).
3. try await attend le résultat et propage une erreur en cas d'échec.
4. do / catch permet d'afficher un message lisible plutôt que de faire planter l'app.
AuthManager.swift 
import Foundation
import Combine
import FirebaseAuth

@MainActor
final class AuthManager: ObservableObject {
    @Published var user: User?
    @Published var isAuthenticated = false
    @Published var errorMessage: String?

    func signUp(email: String, password: String) {
        Task {
            do {
                let result = try await Auth.auth().createUser(
                    withEmail: email,
                    password: password
                )
                self.user = result.user
                self.isAuthenticated = true
                self.errorMessage = nil
            } catch {
                self.errorMessage = error.localizedDescription
            }
        }
    }

    func signIn(email: String, password: String) {
        Task {
            do {
                let result = try await Auth.auth().signIn(
                    withEmail: email,
                    password: password
                )
                self.user = result.user
                self.isAuthenticated = true
                self.errorMessage = nil
            } catch {
                self.errorMessage = error.localizedDescription
            }
        }
    }

    func signOut() {
        do {
            try Auth.auth().signOut()
            user = nil
            isAuthenticated = false
            errorMessage = nil
        } catch {
            errorMessage = error.localizedDescription
        }
    }
}
✓ Objectif de validation : Cmd + B compile sans erreur avec AuthManager.
Étape 6 AuthView.swift

Construire l'écran de connexion et d'inscription

Cet écran contient deux champs (email et mot de passe) et deux boutons : Se connecter et Créer un compte. Les boutons Google et Apple seront ajoutés aux étapes suivantes.

🎯 Règle d'interface : les champs email et mot de passe sont locaux à la vue (@State), tandis que l'état de connexion vient de AuthManager (@ObservedObject).
1. TextField pour l'email, SecureField pour le mot de passe.
2. .textInputAutocapitalization(.never) évite les majuscules automatiques dans l'email.
3. Affichez authManager.errorMessage dans un Text rouge pour expliquer les échecs.
4. Les boutons appellent simplement les méthodes de AuthManager.
AuthView.swift 
import SwiftUI

struct AuthView: View {
    @ObservedObject var authManager: AuthManager
    @State private var email = ""
    @State private var password = ""

    var body: some View {
        ScrollView {
            VStack(spacing: 16) {
                Text("Bienvenue")
                    .font(.largeTitle.bold())

                TextField("Adresse email", text: $email)
                    .textFieldStyle(.roundedBorder)
                    .textInputAutocapitalization(.never)
                    .keyboardType(.emailAddress)

                SecureField("Mot de passe", text: $password)
                    .textFieldStyle(.roundedBorder)

                if let error = authManager.errorMessage {
                    Text(error)
                        .font(.caption)
                        .foregroundStyle(.red)
                        .multilineTextAlignment(.center)
                }

                Button("Se connecter") {
                    authManager.signIn(email: email, password: password)
                }
                .buttonStyle(.borderedProminent)

                Button("Créer un compte") {
                    authManager.signUp(email: email, password: password)
                }
            }
            .padding()
        }
    }
}
✓ Objectif de validation : L'écran s'affiche et les boutons email appellent bien AuthManager.
Étape 7 ContentView.swift & HomeView.swift

Afficher l'écran connecté et gérer la déconnexion

Une vue racine choisit automatiquement entre l'écran d'authentification et l'écran principal selon isAuthenticated. La déconnexion ramène immédiatement à l'écran de connexion.

ContentView
Crée AuthManager avec @StateObject et choisit la vue à afficher.
HomeView
Affiche l'email de l'utilisateur et un bouton Se déconnecter.
signOut()
Appelle Auth.auth().signOut() et remet isAuthenticated à false.
ContentView.swift 
import SwiftUI

struct ContentView: View {
    @StateObject private var authManager = AuthManager()

    var body: some View {
        Group {
            if authManager.isAuthenticated {
                HomeView(authManager: authManager)
            } else {
                AuthView(authManager: authManager)
            }
        }
    }
}
HomeView.swift 
import SwiftUI

struct HomeView: View {
    @ObservedObject var authManager: AuthManager

    var body: some View {
        VStack(spacing: 20) {
            Text("Vous êtes connecté")
                .font(.title.bold())

            Text(authManager.user?.email ?? "Email inconnu")
                .foregroundStyle(.secondary)

            Button("Se déconnecter") {
                authManager.signOut()
            }
            .buttonStyle(.borderedProminent)
        }
        .padding()
    }
}
✓ Objectif de validation : Après connexion, l'écran principal s'affiche ; après déconnexion, l'écran de connexion revient.
Étape 8 GoogleSignIn-iOS & URL Types

Google Sign-In : préparer Xcode

Google Sign-In utilise un package séparé de Firebase. Il faut aussi autoriser l'application à être rouverte par Google après la connexion, via un URL Scheme.

1. File > Add Package Dependencies... puis ajoutez https://github.com/google/GoogleSignIn-iOS.
2. Ajoutez les produits GoogleSignIn et GoogleSignInSwift à votre target.
3. Target > Build Settings > Other Linker Flags : ajoutez -ObjC.
4. Ouvrez GoogleService-Info.plist, copiez la valeur de REVERSED_CLIENT_ID.
5. Target > Info > URL Types > + > collez cette valeur dans URL Schemes.
⚠️ Sans le flag -ObjC, Google Sign-In peut planter au lancement. Sans l'URL Scheme, la fenêtre Google se ferme mais l'app ne reçoit jamais la réponse.
✓ Objectif de validation : Le projet compile et l'URL Scheme REVERSED_CLIENT_ID est présent dans l'onglet Info.
Étape 9 AuthManager.swift & VotreApp.swift

Google Sign-In : connecter le compte à Firebase

Le SDK Google affiche la fenêtre de choix de compte et renvoie un jeton d'identité. On transforme ce jeton en AuthCredential Firebase, puis on appelle Auth.auth().signIn(with:).

💡 La fonction onOpenURL est indispensable : elle permet à Google de transmettre le résultat de la connexion à votre application après avoir quitté Safari.
1. Google a besoin d'un UIViewController pour présenter sa fenêtre. L'extension UIApplication fournit le contrôleur racine.
2. Le clientID se trouve dans la configuration Firebase, pas dans votre code.
3. On crée le credential avec l'ID token et l'access token, puis on le donne à Firebase.
UIApplication+Root.swift 
import UIKit

extension UIApplication {
    var rootViewController: UIViewController? {
        connectedScenes
            .compactMap { $0 as? UIWindowScene }
            .first { $0.activationState == .foregroundActive }?
            .windows
            .first { $0.isKeyWindow }?
            .rootViewController
    }
}
Ajoutez ces imports en haut de AuthManager.swift : import FirebaseCore, import GoogleSignIn et import UIKit.
AuthManager.swift (ajout) 
func signInWithGoogle() {
    Task {
        do {
            guard let clientID = FirebaseApp.app()?.options.clientID else {
                self.errorMessage = "Client ID Google introuvable."
                return
            }

            GIDSignIn.sharedInstance.configuration = GIDConfiguration(clientID: clientID)

            guard let rootViewController = UIApplication.shared.rootViewController else {
                self.errorMessage = "Écran principal introuvable."
                return
            }

            let googleResult = try await GIDSignIn.sharedInstance.signIn(
                withPresenting: rootViewController
            )

            guard let idToken = googleResult.user.idToken?.tokenString else {
                self.errorMessage = "Jeton Google introuvable."
                return
            }

            let credential = GoogleAuthProvider.credential(
                withIDToken: idToken,
                accessToken: googleResult.user.accessToken.tokenString
            )

            let authResult = try await Auth.auth().signIn(with: credential)
            self.user = authResult.user
            self.isAuthenticated = true
            self.errorMessage = nil
        } catch {
            self.errorMessage = error.localizedDescription
        }
    }
}

Étape 10 Signing & Capabilities

Sign in with Apple : activer la capacité et Firebase

Sign in with Apple permet à l'utilisateur de se connecter avec son identifiant Apple, sans créer de mot de passe. C'est le fournisseur le plus exigeant en configuration.

⚠️ Prérequis : un compte Apple Developer Program payant. Sans lui, la capacité Sign in with Apple n'apparaît pas. Dans ce cas, terminez Email + Google et revenez plus tard.
1. Dans Xcode : target > Signing & Capabilities > + Capability > Sign in with Apple.
2. Dans la console Firebase : Authentication > Sign-in method > Apple > Activer.
3. Renseignez le Service ID, le Team ID, le Key ID et la clé privée Apple, ainsi que l'URL de retour https://VOTRE_PROJECT_ID.firebaseapp.com/__/auth/handler.
4. Vérifiez que votre Bundle Identifier dans Xcode correspond à celui enregistré côté Apple et Firebase.
Si l'option Apple est grisée dans Firebase, c'est que la configuration Apple Developer n'est pas terminée. Firebase a besoin de la clé privée .p8 téléchargée depuis le portail Apple Developer. Cette clé ne se télécharge qu'une seule fois : conservez-la précieusement.
✓ Objectif de validation : La capacité Sign in with Apple apparaît dans Xcode et le fournisseur Apple est activé dans Firebase.
Étape 11 AppleSignInHelper.swift & AuthManager.swift

Sign in with Apple : nonce, credential et connexion

Apple exige un nonce : une chaîne aléatoire envoyée à Apple, puis vérifiée par Firebase. Cela empêche qu'un jeton intercepté soit rejoué par un autre site.

🎯 Le nonce brut est conservé dans l'app, tandis que sa version hachée en SHA-256 est envoyée à Apple. Firebase recalcule le hash et compare.
1. SecRandomCopyBytes génère des octets aléatoires sûrs.
2. SHA256.hash vient de CryptoKit.
3. SignInWithAppleButton gère l'interface officielle Apple.
4. Dans onCompletion, on récupère le jeton Apple et on crée le credential Firebase.
AppleSignInHelper.swift 
import Foundation
import CryptoKit
import Security

func randomNonceString(length: Int = 32) -> String {
    var randomBytes = [UInt8](repeating: 0, count: length)
    let errorCode = SecRandomCopyBytes(
        kSecRandomDefault,
        randomBytes.count,
        &randomBytes
    )
    if errorCode != errSecSuccess {
        fatalError("Impossible de générer un nonce.")
    }

    let charset: [Character] = Array(
        "0123456789ABCDEFGHIJKLMNOPQRSTUVXYZabcdefghijklmnopqrstuvwxyz-._"
    )
    return String(randomBytes.map { charset[Int($0) % charset.count] })
}

func sha256(_ input: String) -> String {
    let inputData = Data(input.utf8)
    let hashedData = SHA256.hash(data: inputData)
    return hashedData.map { String(format: "%02x", $0) }.joined()
}

AuthManager.swift (ajout) 
@Published var currentNonce: String?

func signInWithApple(
    credential: ASAuthorizationAppleIDCredential,
    nonce: String
) {
    Task {
        do {
            guard let appleIDToken = credential.identityToken,
                  let idTokenString = String(data: appleIDToken, encoding: .utf8)
            else {
                self.errorMessage = "Jeton Apple introuvable."
                return
            }

            let firebaseCredential = OAuthProvider.appleCredential(
                withIDToken: idTokenString,
                rawNonce: nonce,
                fullName: credential.fullName
            )

            let authResult = try await Auth.auth().signIn(with: firebaseCredential)
            self.user = authResult.user
            self.isAuthenticated = true
            self.errorMessage = nil
        } catch {
            self.errorMessage = error.localizedDescription
        }
    }
}

SignInWithAppleButton(.signIn) { request in
    let nonce = randomNonceString()
    authManager.currentNonce = nonce
    request.requestedScopes = [.fullName, .email]
    request.nonce = sha256(nonce)
} onCompletion: { result in
    switch result {
    case .success(let authorization):
        guard let credential = authorization.credential
            as? ASAuthorizationAppleIDCredential,
            let nonce = authManager.currentNonce else {
            return
        }
        authManager.signInWithApple(
            credential: credential,
            nonce: nonce
        )
    case .failure(let error):
        authManager.errorMessage = error.localizedDescription
    }
}

Étape 12 Tests & dépannage

Tester les trois parcours et corriger les erreurs

Votre module est terminé lorsque les trois parcours fonctionnent : inscription email, connexion Google, connexion Apple, puis déconnexion.

✅ Scénario Email
Créer un compte avec un email valide et un mot de passe d'au moins 6 caractères, se déconnecter, puis se reconnecter.
✅ Scénario Google
Appuyer sur le bouton Google, choisir un compte, vérifier que l'écran principal affiche l'email Google.
✅ Scénario Apple
Appuyer sur le bouton Apple, autoriser, vérifier la connexion. Tester sur un appareil réel si le simulateur bloque.
✅ Scénario Déconnexion
Depuis l'écran principal, se déconnecter et vérifier le retour immédiat à l'écran de connexion.
« FirebaseApp.configure() has not been called » : l'initialisation manque dans le init() de l'App, ou le plist n'est pas dans la target.
« The supplied auth credential is malformed » : le Bundle Identifier ne correspond pas à celui enregistré dans Firebase.
« OPERATION_NOT_ALLOWED » : le fournisseur n'est pas activé dans Authentication > Sign-in method.
Google ne revient pas dans l'app : URL Scheme REVERSED_CLIENT_ID manquant, ou onOpenURL absent.
« Missing or invalid nonce » : le nonce envoyé à Apple n'est pas le SHA-256 du nonce brut, ou currentNonce a été perdu.
Apple ne s'ouvre pas : capacité Sign in with Apple absente, ou compte Apple Developer non configuré.
Erreur réseau : vérifiez la connexion Internet et que l'appareil/simulateur n'est pas bloqué par un pare-feu.
🔎 Pour diagnostiquer : ouvrez la console Xcode (en bas de la fenêtre) et lisez le message d'erreur complet. Firebase indique souvent précisément le fournisseur ou la configuration en cause.
