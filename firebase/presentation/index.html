01 • Concepts

Pourquoi Firebase Authentication ?

Gérer soi-même les mots de passe, les sessions et la sécurité est difficile. Firebase fournit un service prêt à l'emploi, utilisé par des milliers d'applications.

⚡

Rapide à intégrer

Quelques lignes de Swift suffisent pour créer un compte et connecter un utilisateur.

🔐

Sécurisé par défaut

Les mots de passe sont hachés et gérés par Google. Vous ne les stockez jamais vous-même.

🔗

Multi-fournisseurs

Un même utilisateur peut se connecter par email, Google ou Apple.

💡 À retenir : Firebase Authentication gère l'identité. Il ne remplace pas une base de données : les données métier de votre app restent dans Firestore, une API ou un stockage local.
02 • Objectif

Ce que vous allez construire

Une seule classe AuthManager pilote l'état de connexion. Les vues SwiftUI observent cet état et s'affichent automatiquement.

📝
AuthView
Email, mot de passe, boutons Google et Apple.
🧠
AuthManager
Inscription, connexion, déconnexion et erreurs.
🔥
Firebase
Vérifie les identifiants et renvoie l'utilisateur.
🏠
HomeView
Écran connecté avec email et déconnexion.
🔄 Flux : l'utilisateur remplit le formulaire → AuthManager appelle Firebase → Firebase répond → isAuthenticated passe à true → SwiftUI affiche HomeView.

04 • Console Firebase

Créer le projet et enregistrer l'app iOS

Toute la configuration commence dans la console Firebase.

1
console.firebase.google.com
Connectez-vous avec votre compte Google, puis « Créer un projet ».
2
Ajouter une application iOS
Cliquez sur l'icône iOS+ dans la vue d'ensemble du projet.
3
Saisir le Bundle Identifier exact
Xcode > target > Signing & Capabilities > Bundle Identifier. Un seul caractère différent = échec.
❌ Ne créez pas un Bundle Identifier « au hasard » pour Firebase : il doit être identique à celui de votre app Xcode.
05 • Fichier de configuration

Ajouter GoogleService-Info.plist

Ce fichier contient les identifiants publics de votre projet Firebase. Il doit être ajouté à la target de votre application.

Procédure

  1. Télécharger le fichier depuis la console Firebase.
  2. Le glisser dans le navigateur de projet Xcode.
  3. Cocher Copy items if needed.
  4. Vérifier la case de votre target dans Add to targets.

Erreurs classiques

  • • Fichier nommé GoogleService-Info (2).plist
  • • Fichier ajouté au projet mais pas à la target
  • • Ancien fichier conservé après activation de Google
💡 Le nom doit être exactement GoogleService-Info.plist. Firebase le cherche à cet emplacement au démarrage.

07 • Code

Initialiser Firebase au démarrage

Dans une app SwiftUI, l'initialisation se fait dans le init() de la structure @main.

VotreApp.swift
import SwiftUI
import FirebaseCore

@main
struct MonApp: App {
    init() {
        FirebaseApp.configure()
    }

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}
❌ Oublier FirebaseApp.configure() provoque l'erreur « FirebaseApp.configure() has not been called » dès la première requête d'authentification.
08 • Console Firebase

Activer les trois fournisseurs

Authentication > Sign-in method. Aucun fournisseur n'est actif par défaut.

✉️ Email / Mot de passe

Activer, puis enregistrer. C'est le fournisseur le plus simple à tester.

🔴 Google

Activer, enregistrer, puis retélécharger le fichier plist et remplacer l'ancien.

🍎 Apple

Activer et configurer le Service ID, Team ID, Key ID et la clé privée Apple.

⚠️ Si Firebase renvoie OPERATION_NOT_ALLOWED, le fournisseur n'est pas activé. Ce n'est pas un bug de votre code Swift.
09 • Email / Mot de passe

Inscription : createUser

La méthode createUser(withEmail:password:) crée un compte Firebase et connecte immédiatement l'utilisateur.

AuthManager.swift
func signUp(email: String, password: String) {
    Task {
        do {
            let result = try await Auth.auth().createUser(
                withEmail: email,
                password: password
            )
            self.user = result.user
            self.isAuthenticated = true
            self.errorMessage = nil
        } catch {
            self.errorMessage = error.localizedDescription
        }
    }
}
💡 Task { } lance une opération asynchrone : Firebase a besoin du réseau.
💡 do / catch évite de faire planter l'app en cas d'email déjà utilisé.
10 • Email / Mot de passe

Connexion : signIn

La méthode signIn(withEmail:password:) vérifie les identifiants auprès de Firebase.

AuthManager.swift
func signIn(email: String, password: String) {
    Task {
        do {
            let result = try await Auth.auth().signIn(
                withEmail: email,
                password: password
            )
            self.user = result.user
            self.isAuthenticated = true
            self.errorMessage = nil
        } catch {
            self.errorMessage = error.localizedDescription
        }
    }
}
🔐 Firebase exige un mot de passe d'au moins 6 caractères. Un email déjà utilisé renvoie une erreur explicite dans error.localizedDescription.
11 • Email / Mot de passe

Déconnexion : signOut

La déconnexion supprime l'utilisateur courant côté Firebase et remet l'état de l'app à zéro.

AuthManager.swift
func signOut() {
    do {
        try Auth.auth().signOut()
        user = nil
        isAuthenticated = false
        errorMessage = nil
    } catch {
        errorMessage = error.localizedDescription
    }
}
✅ Une fois isAuthenticated repassé à false, la vue racine SwiftUI réaffiche automatiquement l'écran de connexion.
12 • Architecture SwiftUI

Relier l'état à l'interface

La vue racine observe AuthManager et choisit l'écran à afficher. Testez le principe avec la démo ci-dessous.

ContentView.swift
struct ContentView: View {
    @StateObject private var authManager = AuthManager()

    var body: some View {
        Group {
            if authManager.isAuthenticated {
                HomeView(authManager: authManager)
            } else {
                AuthView(authManager: authManager)
            }
        }
    }
}

Démo visuelle (non connectée à Firebase)

Simulez le comportement du formulaire. Aucune donnée n'est envoyée.

13 • Google Sign-In

Google Sign-In : configuration Xcode

Google utilise un package séparé et un URL Scheme pour rouvrir votre app après la connexion.

1. Package

Ajouter https://github.com/google/GoogleSignIn-iOS puis les produits GoogleSignIn et GoogleSignInSwift.

2. Linker

Build Settings > Other Linker Flags > ajouter -ObjC.

3. URL Scheme

Copier REVERSED_CLIENT_ID depuis le plist, puis Target > Info > URL Types > + > URL Schemes.

4. onOpenURL

Transmettre l'URL reçue à GIDSignIn.sharedInstance.handle(url).

14 • Google Sign-In

Google Sign-In : le code

On récupère le jeton Google, puis on crée un credential Firebase.

AuthManager.swift
let googleResult = try await GIDSignIn.sharedInstance.signIn(
    withPresenting: rootViewController
)

guard let idToken = googleResult.user.idToken?.tokenString else {
    return
}

let credential = GoogleAuthProvider.credential(
    withIDToken: idToken,
    accessToken: googleResult.user.accessToken.tokenString
)

let authResult = try await Auth.auth().signIn(with: credential)
user = authResult.user
isAuthenticated = true
❌ URL Scheme manquant = la fenêtre Google se ferme sans revenir dans l'app.
❌ -ObjC manquant = risque de crash au lancement.
15 • Sign in with Apple

Apple : la configuration la plus exigeante

Apple exige un compte développeur payant, une capacité Xcode et une configuration dans Firebase.

1
Capability Xcode
Signing & Capabilities > + Capability > Sign in with Apple.
2
Firebase Console
Authentication > Sign-in method > Apple > Activer.
3
Identifiants Apple
Service ID, Team ID, Key ID, clé privée .p8 et URL de retour Firebase.
⚠️ La clé privée Apple ne se télécharge qu'une seule fois. Conservez-la. Ne la partagez jamais et ne la commitez pas dans Git.
16 • Sign in with Apple

Apple : nonce et credential Firebase

Apple renvoie un jeton d'identité. On le combine au nonce brut pour créer le credential Firebase.

AuthManager.swift
let credential = OAuthProvider.appleCredential(
    withIDToken: idTokenString,
    rawNonce: nonce,
    fullName: appleCredential.fullName
)

let authResult = try await Auth.auth().signIn(with: credential)
user = authResult.user
isAuthenticated = true
🔐 Le nonce brut reste dans l'app. C'est son hash SHA-256 qui part chez Apple. Firebase recalcule le hash et compare.
❌ « Missing or invalid nonce » = le hash SHA-256 n'a pas été envoyé, ou le nonce brut a été perdu.
17 • Dépannage

Les erreurs les plus fréquentes

Lisez toujours le message complet dans la console Xcode : Firebase indique souvent la cause exacte.

FirebaseApp.configure() has not been called
Initialisation absente ou plist hors target.
The supplied auth credential is malformed
Bundle Identifier différent de celui de Firebase.
OPERATION_NOT_ALLOWED
Fournisseur non activé dans la console.
Google ne revient pas dans l'app
URL Scheme ou onOpenURL manquant.
Missing or invalid nonce
Hash SHA-256 du nonce incorrect ou perdu.
Apple ne s'ouvre pas
Capability absente ou compte Apple Developer non configuré.
