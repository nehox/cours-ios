Partie 1 • L'Écosystème

Pourquoi Swift est unique en son genre ?

Né chez Apple en 2014 pour remplacer Objective-C, conçu pour la sécurité et la vitesse.

🛡️

1. Sûr par Conception

En Swift, les bugs de type NullPointerException ou undefined is not a function sont impossibles à la compilation grâce au système d'Optionnels.

Le compilateur détecte les erreurs avant même de lancer l'application.
⚡️

2. Ultra Rapide (LLVM)

Langage compilé directement en code machine natif via LLVM. Pas de machine virtuelle, pas de Garbage Collector lourd : gestion de mémoire instantanée via ARC (Automatic Reference Counting).

Performances comparables au C++ avec la clarté de Python.
💎

3. Expressif & Moderne

Inférence de types, génériques puissants, pattern matching, closures fluides et concurrence moderne (async/await, Actors).

Moins de code boilerplate, plus de valeur métier.
💡
Règle d'or pour un développeur iOS : Le compilateur Swift est exigeant, mais c'est votre meilleur allié. S'il refuse de compiler, c'est qu'il vient de vous éviter un crash utilisateur en production !
Partie 2 • Les Fondations (Lesson 01)

Variables, Types & Immuabilité

La règle fondamentale : privilégiez toujours let avant var.

Basics.swift 
// 1. Constante (Immuable - Recommandé !)
let maximumStudents: Int = 30
// maximumStudents = 32  ❌ Erreur de compilation : Cannot assign to 'let'

// 2. Inférence de type (Swift devine pour vous)
let courseTitle = "Cours iOS & TDD"   // String automatique
var currentAttendees = 25              // Int modifiable

// 3. Mutation contrôlée
currentAttendees += 1                  // ✅ OK : var est mutable

// 4. Interpolation de chaînes
let status = "\(courseTitle) : \(currentAttendees)/\(maximumStudents)"
print(status)
// Affiche : "Cours iOS & TDD : 26/30"

let vs var

Utilisez let par défaut à 95%. Si votre variable n'a pas besoin de changer, verrouillez-la ! Cela garantit la sécurité en environnement multi-thread et évite les bugs de mutation inattendue.

Inférence de Types Forte

Swift est à typage statique strict. Vous n'avez pas besoin d'écrire let x: String = "Hello", écrire let x = "Hello" est tout aussi sûr et beaucoup plus lisible.

Dans votre TP (Lesson 01)
struct Lesson01Basics {
  let title: String
  let objective: String
}

Une simple structure avec des propriétés immuables suffit à représenter un modèle fiable et testable.

Partie 2 • Modèles

Struct vs Class : Le Choix Crucial

Value Types (Copie par valeur) vs Reference Types (Partage d'adresse). Testez l'interactivité ci-dessous !

Cliquez pour comparer

Struct (Value Type) : Copie intégrale indépendante

Modifier 'b' ne touche JAMAIS 'a'. Chaque variable possède sa propre boîte en mémoire (Stack).

variable a
title = "Tâche A"
Adresse : 0xStack01
variable b (copie)
title = "Tâche Modifiée"
Adresse : 0xStack02 (Indépendant)
⚠️ Les deux variables pointent vers le même objet en Heap : 0xHeap99
Recommandation Apple : Préférez toujours struct pour vos modèles de données (`Task`, `User`). Réservez class pour vos ViewModels ou les ressources partagées.
⚡️ Quiz Flash #1 • Les Fondations Question 1/2

Observez ce code Swift. Que se passe-t-il lors de la compilation ? 

let taskCount = 10
taskCount = 12
print(taskCount)
Explication : En Swift, let déclare une valeur strictement immuable. Le compilateur refuse catégoriquement toute réassignation dès l'analyse statique du code. Pour pouvoir modifier taskCount, il aurait fallu utiliser var.
Partie 3 • La Sécurité (Lesson 02)

Le Boss Final : Les Optionnels (T?)

Pourquoi nil en Swift n'est pas le null des autres langages ?

Métaphore de la Boîte Mystère
📦
"Swift 5.10"
Représentation interne dans Swift :
.some("Swift 5.10")

Un type String? n'est PAS une chaîne de caractères. C'est un conteneur (une boîte) qui contient soit une chaîne, soit rien (nil). On doit obligatoirement l'ouvrir pour y toucher !

1. if let (Déballage classique) if let title { ... }
✓ Exécuté : "Le titre est Swift 5.10"
2. guard let (Sortie précoce - Idiomatique Swift) guard let title else { return }
✓ Passe le garde : continue avec "Swift 5.10"
3. Nil-Coalescing (Valeur par défaut) title ?? "Sans titre"
"Swift 5.10" (valeur déballée)
⚠️ Force Unwrap (L'interdit) title!
"Swift 5.10" (OK mais risqué)
Partie 3 • Sécurisation (Lesson 02)

L'élégance de guard let

Le pattern officiel d'Apple pour éviter la "Pyramide du Destin" (imbrications infinies de if).

❌ Approche naïve (Pyramide) Difficile à lire 
func processTask(title: String?) {
    if let title = title {
        let trimmed = title.trimmingCharacters(in: .whitespaces)
        if !trimmed.isEmpty {
            // Enfin le code métier au 3ème niveau d'indentation !
            save(trimmed)
        }
    }
}
✅ Approche Swift Idiomatique (Lesson 02) Clean & Testable 
enum Lesson02Optionals {
    static func trimmedTitle(from title: String?) -> String? {
        // Sortie précoce immédiate si nil !
        guard let title else {
            return nil
        }

        let candidate = title.trimmingCharacters(in: .whitespacesAndNewlines)
        return candidate.isEmpty ? nil : candidate
    }
}

🚪 La philosophie du "Bouncer" (Videur à l'entrée)

Le mot-clé guard teste les conditions nécessaires dès la première ligne. Si la donnée est invalide ou nil, la fonction quitte immédiatement avec un return ou throw.

🎯 Portée de la variable déballée

Contrairement à if let où la variable déballée n'existe que dans les accolades du bloc, avec guard let title, la variable title reste disponible dans tout le reste de la fonction !

⚡️ Objectif TP : Vous utiliserez cette fonction dans vos tests de validation pour rejeter les tâches vides ou ne contenant que des espaces.
Partie 4 • Architecture (Lesson 03)

Protocoles & Injection de Dépendances

Comment écrire du code découplé qui se teste en quelques millisecondes.

Lesson03_Protocols.swift 
// 1. Le Contrat (Interface)
protocol Lesson03TaskProviding {
    func currentTasks() -> [ProductivityTask]
}

// 2. L'implémentation de Test (Mock)
struct Lesson03MockProvider: Lesson03TaskProviding {
    let tasks: [ProductivityTask]

    func currentTasks() -> [ProductivityTask] {
        tasks
    }
}

// 3. L'implémentation Réelle (Base de données / API)
final class TaskStore: Lesson03TaskProviding {
    func currentTasks() -> [ProductivityTask] {
        // Lit depuis le disque ou CoreData/SwiftData...
    }
}

Qu'est-ce qu'un Protocole ?

C'est une promesse. Il spécifie quelles méthodes ou propriétés un objet doit posséder, sans se soucier de comment elles sont implémentées.

Le Secret des Apps Testables

Votre interface graphique (View) ou votre logique métier (ViewModel) ne doit jamais appeler directement une base de données ou un serveur réseau. Elle doit dépendre d'un protocol.

ViewModel ➔ dépend de ➔ TaskProviding ➔ injecte ➔ MockProvider
💡 Résultat : Vous pouvez tester toute votre application sur simulateur ou en CI sans aucune connexion Internet ni base de données réelle !
Partie 4 • Qualité Pro

Le Cycle TDD : Rouge ➔ Vert ➔ Refactor

Pourquoi écrire le test unitaire avant ou pendant l'implémentation change la donne.

🔴 Étape 1

1. Écrire le Test (Rouge)

On commence par exprimer l'attente métier dans un test unitaire avec XCTest. Le test échoue car le code n'existe pas encore.

❌ FAILED : test failed

2. Faire Passer (Vert)

On implémente le code le plus simple possible pour faire passer le test au vert. Pas de sur-ingénierie prématurée.

Product > Test (Cmd + U)

3. Refactoriser

Maintenant que le test veille sur vous comme un filet de sécurité, vous pouvez nettoyer les noms, optimiser et découper le code sans peur de casser quoi que ce soit !

Répétez en toute confiance.

Partie 5 • UI & Architecture (Lesson 04 & 05)

SwiftUI & MVVM : View = f(State)

L'interface utilisateur n'est plus impérative, elle est la projection directe de votre ViewModel.

M • Modèle (Données)

ProductivityTask

Pure structure Swift immuable avec un identifiant unique (UUID), un titre et une priorité.

struct ProductivityTask {
  let id: UUID
  var title: String
  var isDone: Bool
}
VM • ViewModel (Cerveau)

HomeScreenViewModel

Classe ObservableObject annotée @MainActor. Elle expose des propriétés @Published que l'écran observe.

@Published var tasks
var completedCount: Int
func markTaskDone(...)
V • View (Interface SwiftUI)

ProductivityHomeView

Structure légère conforme au protocole View. Elle écoute le ViewModel et redessine l'écran dès que les données changent.

struct ...: View {
  @ObservedObject var vm
  var body: some View { ... }
}
🎯 Pourquoi c'est génial ? Zéro logique métier dans la vue SwiftUI. Toute la logique est dans le ViewModel et se teste automatiquement en un clin d'œil sans avoir besoin de cliquer sur l'écran !
Partie 5 • Layout & Structure

Les Piliers du Layout : VStack, HStack & ZStack

En SwiftUI, toute votre interface est construite en combinant ces trois briques fondamentales.

Démonstrateur Interactif

VStack (Vertical Stack • Colonne)

Empile les composants de haut en bas sur l'axe vertical Y. Idéal pour structurer les formulaires, écrans et listes.

1. En-tête de vue (Header) Élément A
2. Carte de résumé (SummaryCard) Élément B
3. Liste de tâches (TasksSection) Élément C
Syntaxe SwiftUI Live Code 
VStack(alignment: .leading, spacing: 12) {
    Text("Titre de la tâche")
        .font(.headline)
    Text("Priorité Haute")
        .font(.subheadline)
        .foregroundStyle(.secondary)
    Button("Marquer comme fait") { ... }
}
↔️ Le Super-Pouvoir de Spacer()

Spacer() agit comme un ressort compressible infini. Placé entre deux éléments dans un HStack ou VStack, il repousse les éléments vers les extrémités de l'écran.

Partie 5 • Composants Visuels

Text, Label, Button & Ordre des Modificateurs

Les composants graphiques atomiques d'Apple et la règle cruciale des modificateurs en cascade.

✍️

Text & Typographie

Utilisez toujours les styles sémantiques Apple pour respecter automatiquement la taille de police préférée de l'utilisateur (Dynamic Type).

.font(.largeTitle.bold())
.font(.headline)
.foregroundStyle(.secondary)
S'adapte en mode sombre automatiquement.
🌟

Label & SF Symbols

Apple fournit plus de 5 000 icônes vectorielles natives parfaites. Label associe texte et icône avec un alignement impeccable.

Label("Priorité", systemImage: "flag.fill")
Image(systemName: "checkmark.circle.fill")
Colorable via .foregroundStyle(.orange).
🔘

Button & Styles

Le composant d'action par excellence. Avec iOS 15+, finis les styles manuels lourds, utilisez les styles système d'Apple !

Button("Action") { ... }
  .buttonStyle(.borderedProminent)
  .tint(.orange)
Gère les animations de tap nativement.
⚠️
L'ordre des modificateurs compte énormément !
Text("A").padding().background(.blue) colore le texte AVEC ses marges, alors que Text("A").background(.blue).padding() colore uniquement le texte sans marges !

Partie 5 • Démo Live Interactive

Le Composant Réel : Code SwiftUI & Rendu iOS

Cliquez sur les tâches dans l'iPhone ci-contre pour tester la réactivité SwiftUI en direct !

ProductivityHomeView.swift ● Preview SwiftUI 
import SwiftUI

struct ProductivityHomeView: View {
    @ObservedObject var viewModel: Lesson05HomeScreenViewModel

    var body: some View {
        ScrollView {
            VStack(alignment: .leading, spacing: 20) {
                // En-tête dynamique
                headerSection
                
                // Carte de résumé calculée en direct
                summaryCard
                
                // Liste des tâches réactive
                tasksSection
            }
            .padding(24)
        }
        .background(Color(.systemGroupedBackground))
    }

    private var summaryCard: some View {
        HStack {
            Text(viewModel.completedCountText)
                .font(.title2.bold())
            Spacer()
            Text(viewModel.pendingCountText)
                .foregroundStyle(.secondary)
        }
        .padding()
        .background(.white, in: RoundedRectangle(cornerRadius: 16))
    }
}

⚡️ Quiz Flash #2 • Les Optionnels Question 2/2

Que va afficher cette ligne de code en console ? 

let userNickname: String? = nil
let displayName = userNickname ?? "Invité"
print("Bonjour, \(displayName) !")
Explication : L'opérateur de coalescence ?? (Nil-Coalescing) permet de déballer un optionnel en toute sécurité en fournissant une valeur de secours si l'optionnel vaut nil. Aucun crash n'est possible !
